Formula Structure
Fit two outcomes jointly, optionally with an estimated residual correlation between them.
A response gets a genuine nonlinear function (e.g. a decay curve) instead of a sum of linear terms — each nonlinear parameter gets its own small formula.
Predictor Types
A predictor may have a flexible, smooth (not necessarily linear) curve — s(x).
Ordinal predictor (e.g. education level): effect assumed monotonic, but NOT equal step sizes — mo(x).
A predictor may have a flexible, smooth curve — like s(x), but modeled via a Gaussian process instead of a spline basis — gp(x).
The observed x-value is a noisy measurement of a latent true value — me(x, sd_x).
Data Peculiarities
Two routes: brms-internal imputation (mi()) or external multiple imputation with mice + brm_multiple().
Response values are known only up to a bound (cens(), e.g. "survived longer than 30 days") or cannot in principle take certain values (trunc(), e.g. instrument range).
Grouping & Correlation
Instead of "everything correlates automatically": explicitly uncorrelated (||) or only specific terms tied together via a shared ID tag (|p|, |q|, …).
An observation belongs to MULTIPLE levels of the same grouping at once, e.g. with weights (a student with two teachers this term) — mm().
Observations are correlated over time (ar/ma/arma) or space (car), not independent — e.g. repeated measures with trending residuals, or regions with a neighborhood structure.
Distribution & Priors
Many candidate predictors, probably only a few genuinely relevant: the horseshoe prior automatically shrinks most coefficients toward zero. Then use projpred to identify the most important predictors.
Your observations probably come from several unobserved subgroups, each with its own distribution (e.g. two reaction-time regimes, "fast guess" vs. "deliberate") — mixture(fam(), fam(), ...) instead of a single family.
A value computed in R (e.g. a data-derived mean/SD for a prior) is otherwise unknown to Stan — stanvar() declares it as a genuine Stan variable and passes the value through.

⚠ How to use this tool

This is not a fully automatic model builder. For standard models, use the brms Model Builder — there the generated code runs directly.

This tool is for rare, advanced building blocks that don't fit into the standard model builder — multivariate models, random-effects correlation structures, splines/Gaussian process, nonlinear formulas, autocorrelation, multi-membership, censoring/truncation, hurdle and ordinal families, measurement error and missing data, among others. It assumes experience with brms.

The sidebar on the left builds the code at the top right live. Every documentation card further down has a "✓ Apply directly" button that applies that setting straight into the model. Each card also has a collapsible "🧪 Data simulation" field with R code that generates a small test dataset for exactly that building block. The code in that field can be freely edited; once it is, changes in the sidebar no longer overwrite it automatically — "🔄 Regenerate" deliberately rebuilds it from the current sidebar state, "↺ Reset" also discards the sidebar state and starts over with an empty model.

Priors are deliberately not guessed — the generated code therefore contains no automatically generated priors <- c(...) block, but instead calls get_prior(), which shows which classes/coefficients brms expects for that particular model.

The "✓ Formal check" only checks for structural oddities (parentheses, missing arguments, tag consistency) — it is not a substitute for an actual test run in R (e.g. make_stancode() or a few iterations with sample_prior="only").
